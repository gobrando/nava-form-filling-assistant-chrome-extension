# Nava Form-Filling Assistant — team update

**What it is.** A local-first Chrome extension that brings Nava’s agentic form-filling workflow into the caseworker’s browser. It loads reviewed client data, uses separate AI roles to map fields, identify gaps, and independently review the plan, then executes only locally validated writes. It can continue through approved multi-page flows and always stops before certification, signature, or submission.

## What we shipped recently

- **Real agentic runtimes:** three independent planner roles can run with Chrome’s on-device Gemini Nano, a paired Codex or Claude subscription CLI for internal testing, or Nava’s shared planner API. Client values are removed before model calls; models see bounded form metadata and available data-purpose names, while all proposed writes are validated again locally.
- **Multi-application orchestration:** a durable queue opens known applications in separate tabs, assigns one writer per tab, runs up to three applications concurrently, preserves per-application progress/checkpoints, and supports pause, resume, handoff, tab closure, and expired-session recovery without storing participant values in durable queue state.
- **Live-site compatibility work:** current adapters and safe-navigation rules cover BenefitsCal, Riverside WIC, and Riverside IHSS routes. The runner permits only exact, approved continuation controls and blocks CAPTCHA/OTP, attestations, certification, signatures, and submission. WIC gap analysis now removes stale questions after successful fills and groups unanswered checkbox choices into caseworker-friendly questions.
- **Data intake:** users can import a reviewed organization record through the read-only connector contract or upload PDF, image, Word, text, CSV, or JSON documents. The self-service connector catalog includes Apricot plus provisioned-adapter paths for Salesforce, HMIS, and other common systems; credentials remain server-side.
- **OCR quality gate:** six fictional fixtures achieved **100% precision, 91.2% recall, 100% expected-abstention accuracy, and zero accepted wrong values**. Low-confidence values are withheld for human review rather than guessed.
- **Recertification workflow:** the extension now shows a caseload-level renewal dashboard, sorts overdue and upcoming cases, drafts caseworker alerts and client outreach, tracks five required information areas, records explicit client authorization, and unlocks **Prepare with AI** only when the data is current and the client has opted in.
- **Usage visibility:** application cards and the sanitized activity log track planner calls, model duration, provider-reported tokens/context units when available, and direct API-key cost. On-device and subscription paths report `$0.00` direct API-key cost while clearly noting local-compute or subscription usage.

## Evidence and current boundary

Version **0.11.0** passes **161 automated tests** plus syntax checks. The installed extension completed the passive six-page validation fixture with **28/28 fields across 5/5 data-entry pages**, stopping at review with certification unchecked and submission untouched. On the live Riverside County IHSS form with fictional record `339619`, Gemini Nano verified **32/35 attempted writes in 511.0 seconds**; the Codex subscription runtime verified **34/37 in 127.9 seconds**, using **104,510 input and 6,061 output tokens**. Both stopped before affirmation, Cloudflare, and Submit, but neither was review-ready because required decisions remained unanswered. A real BenefitsCal run reached the name-information page and exposed a cross-page path-policy defect; the fix is implemented and awaiting an installed-extension rerun. We do **not** claim an end-to-end completed live application, production Apricot integration, CAPTCHA bypass, notification delivery, or legal submission.
